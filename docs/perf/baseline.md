# 計測の基準値（MS0）

目的：表示の速さと通信量の基準値を残し、各 MS の効果を同じ条件で比べられるようにする。

- 計測日：2026-11-19（JST）。計測コマンド：`pnpm perf`（`scripts/perf/measure.ts`）。生データ：`baseline-prod.json`・`baseline-local.json`。
- 数値は 3 回の中央値（括弧は最小〜最大）。KB は転送バイト（圧縮後）÷ 1024。

## 1. 発足時の暫定の基準値（2026-11-19、MS1 より前の本番）

### 分かったこと

- 初回の document は 175KB。展開後 1,582KB のうち初期 RSC が 1,479KB（brotli し直しで 73KB の目安）。194 枚分のカードが入っている。
- 2 回目の訪問でも document（175KB）と RSC を取り直す。JS・画像・フォントはキャッシュで 0。2 回目の 195KB はほぼ document。
- 先読み：初回に 15 リクエスト、10 枚スクロールでさらに 26 リクエスト（詳細 1 件につき本体とセグメントの 2 本）。詳細（`/d/`）宛の先読みの転送は計 92KB で、上の初回・スクロールに含まれる。タップした詳細は先読み済みで、タップ後の通信は 0。
- フォントの転送は 0。Supabase 宛のリクエストは未ログインでは 0。
- Save-Data を付けても初回の通信量は変わらない（アプリが Save-Data を見ていないため。MS4 の対象）。

## 4. 記録した環境とデータ

- 実行地点：手元の Mac（日本）から。Vercel の edge は `kix1`（`x-vercel-id`）。関数の region は `vercel.json` の `hnd1`（東京）。Supabase の region は未確認。
- データ件数（anon から読める公開分）：`dest_cards` 560・`regions` 1,990・`dest_photos` 3,272。`/ja` の document に入っているカードは 194 枚。
- 回線：Slow 4G は下り 1.6Mbps・上り 0.75Mbps・RTT 150ms（CDP の `Network.emulateNetworkConditions`）。CPU 4x は `Emulation.setCPUThrottlingRate`。
- Save-Data：リクエストヘッダ `Save-Data: on` と `navigator.connection.saveData = true` を付ける再現。Chromium でデータセーバーの本物の設定は自動化できない。
- 状態：ブラウザキャッシュは「初回 = 空の context」「2 回目 = 同じ context で再訪」。サーバー・画像 CDN は、計測前に 1 回訪問して温めた状態（`PERF_WARMUP=0` で冷たい状態も測れる。今回は未計測）。本番の document は `x-vercel-cache: HIT`。

- `buildFeed` と DB の取得時間の内訳：Server-Timing を出すにはアプリの変更が要る。今回はアプリを変えていないので分けていない。本番の document は `x-vercel-cache: HIT` で返るため、TTFB はサーバー処理の目安にならない。
- ログイン時の Supabase 宛リクエスト数：未測。未ログインは 0。
- 海外からの計測：未取得（手元の Mac からのみ）。
- Supabase の region。
- スクロールの途中の節目や、カタログが 2 倍・5 倍になったときの値（MS2b・MS5 で測る）。
